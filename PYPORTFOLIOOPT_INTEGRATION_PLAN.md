# PyPortfolioOpt-Only Integration Plan (No VNStock/VNDirect/FireAnt in this repo)

> Status (2026-02-27): Deprecated for this repo. Portfolio/forecast intelligence has been moved to Dexter external stock agent.
> Upstream orchestrator now calls stock_agent_external_v1 only for invest flow.

## 1) Boundary Decision (Locked)

This repository will **NOT** integrate market-data fetchers (`vnstock`, VNDirect, FireAnt).

- Market data ownership stays in **Dexter Stock Agent external service**.
- This repository only handles:
  - orchestration,
  - tool-plane contract,
  - optional internal optimization using `PyPortfolioOpt` from provided market snapshot.

This keeps clean architecture boundaries and avoids duplicate data-source logic.

## 2) Objective

Add `PyPortfolioOpt` allocation optimization into Tier-2 flow while preserving current architecture:

- Orchestrator routes `invest` to `stock_agent_external_v1` first.
- Stock Agent returns normalized market snapshot + constraints context.
- New MCP tool runs Efficient Frontier from that snapshot.
- Planner aggregates and responds with explainable allocation options.

## 3) Target Runtime Flow

1. User asks invest/portfolio advisory.
2. Orchestrator calls `stock_agent_external_v1`.
3. Stock Agent response includes `market_snapshot` and optional constraints.
4. Orchestrator calls new tool `portfolio_allocation_optimize_v1` with snapshot.
5. Tool returns weights + performance + reason codes.
6. Response layer merges Stock Agent commentary + optimization output.

Fallback:

- If Stock Agent unavailable -> existing education-only fallback path.
- If snapshot missing/stale -> optimizer returns `status=fallback` with explicit reason codes.

## 4) New Tool Contract (MVP)

Tool name:

- `portfolio_allocation_optimize_v1`

Input:

- `user_id: str`
- `risk_profile: "conservative" | "moderate" | "aggressive"`
- `objective: "max_sharpe" | "min_volatility" | "efficient_risk" | "efficient_return"`
- `target_volatility: float | null`
- `target_return: float | null`
- `market_snapshot: object`
- `constraints: object | null`
- `trace_id: str | null`

`market_snapshot` minimum fields:

- `as_of: ISO timestamp`
- `source: string` (expected `stock_agent_external`)
- `symbols: list[str]`
- `prices: {symbol: [float,...]}` (aligned close-price series)

Output:

- `status: "ok" | "fallback" | "insufficient_input"`
- `weights: [{symbol, weight}]`
- `performance: {expected_return, volatility, sharpe}`
- `optimization: {method, constraints_applied, clipped}`
- `snapshot_meta: {as_of, age_seconds, is_stale}`
- `reason_codes: list[str]`
- standard audit envelope (`trace_id`, `version`, `params_hash`, `sql_snapshot_ts`, `audit`)

## 6) Snapshot Validation Rules

Before optimization:

- Require minimum history length (default 60 points per symbol).
- Require all symbols have aligned series length.
- Reject NaN/inf/non-positive price values.
- Enforce freshness:
  - `PORTFOLIO_SNAPSHOT_MAX_AGE_SECONDS` (hard gate)
  - if stale -> `fallback` + `reason_codes=["stale_market_snapshot"]`

## 7) Optimization Policy Rules (MVP)

- Apply per-profile max risky weight caps.
- Apply per-asset max weight cap.
- Normalize total weight to 1.0.
- If solver fails, return safe fallback with reason code `optimizer_solver_failed`.

No buy/sell execution advice is generated by this tool.
